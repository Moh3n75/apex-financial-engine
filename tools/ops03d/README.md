# OPS-03D repeatable qualification

Use Java 21 and the locally installed Maven 3.9.11. Run `verify-ops03d.ps1 -Offline -Phase Full -MavenCommand <absolute mvn.cmd>`. It creates a short independent clone and a new third-party-seeded Maven repository, verifies no com/apex before the first build and propagates the repository through a dedicated launcher to every nested runner. Do not call Build/Focused a full qualification. No original source clean/stage/commit or shared process cleanup occurs.

Full runs current native/contract/Console tests, each owner, original snapshot v1 and OPS-03B/C packaged scenarios, new high-retention recent discovery and matched load, then the unchanged fixed M35/M35.7 product chain and its external consumer. Every command/native exit is retained. XML/plans/CSV/logs are archived before that chain cleans its owned targets. Packaging skips tests only for prerequisite construction; later explicit commands execute them. Failed first attempts remain separate, never a composed wrapper PASS.

After a successful wrapper, run `python tools/ops03b/junit-ledger.py <source> <out/ops03d/ledger>`, `python tools/ops03d/qualify-policy.py <source> <run>` and `python tools/ops03d/audit.py <source> <run>`. Root OPS-03D acceptance documents alone may be completed after source freeze. Any runtime/test/script delta requires a new freeze/run.

Indexes are MANUAL OWNER REVIEW scripts in each application's `db/ops03d/recent-indexes.sql`, outside Flyway. Apply only to owned disposable DBs for qualification; the fixture does this in one autocommit session. Production migration/index creation remains an owner action. Set owner flags `apex.ops03.owner-enabled`, `apex.ops03d.search-enabled`, `apex.ops03d.indexes-reviewed` and explicit `apex.ops03d.scopes`; existing owner-local read credentials, known groups and mTLS remain required. Grant exact `QUERY:OPS_OWNER_RECENT_SEARCH:1`. Existing search/snapshot grants do not imply this permission.

Console uses its own opt-in `apex.ops03d.search-enabled`, `apex.ops03d.environment`, `apex.ops03d.sources` inventory and existing fixed TLS destinations. It receives no owner JDBC credentials. Recent routes are `/ops/v1/recent/{events,inbox,requests,workflows}`, `/recent/search/sources` and `/recent/search/openapi`. Existing routes remain unchanged. `smoke-read-only.ps1` performs at most three explicit rolling rereads, eight pages/cycle, literal loopback only. It prints partial metadata, does not create orders or write a projection, and is not an unattended scheduler/commit feed.

The 16 recent candidates/page and eight-page budget still truncate dense recent ranges; state filters apply after candidate selection. Recent indexes remove ancient-row starvation, not late-commit/retention/density/clock gaps. Production SLA and automatic reconciliation/projection remain gated. See the seven OPS-03D reports for actual verdicts and missing evidence. `stage-manifest.txt` is review-only; establish the pre-existing uncommitted OPS base before staging any formerly untracked file. Never stage protected YAML/POMs/old reports, out/target/log/cert/evidence or unrelated owner patches.
