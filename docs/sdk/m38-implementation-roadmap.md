# M38 implementation roadmap

This is a proposal following the source audit of `a9202ee69a368cb8b9d8691be20db5ac831a11d0`; no capability implementation is authorized by this document. The SDK is not ready for unrestricted enterprise use. Preserve Cell boundaries, public Java contracts, Java-model gRPC ergonomics and independent service ownership. Use existing Maven boundaries unless a measured dependency-isolation need justifies another module. No central command bus or custom OAuth/JWT cryptography.

Each milestone can be built and tested independently against explicit fixtures. Priority and Definition of Done apply to the whole milestone, not just successful compilation. [Gap analysis](m38-gap-analysis.md) supplies detailed acceptance cases, dependencies and relative complexity; effort ranges below include SDK tests but exclude fixing business applications and setting up production infrastructure. Work touching the same files should be integrated sequentially.

Suggested order: SDK-0 → SDK-1 → SDK-2. SDK-3, SDK-4 and the deployment fixtures can then progress independently; SDK-5 uses the context baseline. SDK-7 follows stable transport handoffs. SDK-8 is the final gate. Do not delay the defined HTTP/async/security work until an entire standalone infrastructure estate is built.

## Ownership and release decisions

SDK owners implement reusable transport/context/runtime behavior and tests. Contract and Cell owners define event versions, resource permissions and atomic request receipts. Identity owners provide issuer/JWKS/claims policy and SSO application behavior. Gateway owners decide edge authentication and credential forwarding. Platform owners provide TLS, Kafka/PostgreSQL/Eureka/Kubernetes, telemetry collector and artifact repository. Console/replay applications retain aggregation, operator workflow and administrative authorization.

Acceptance does not require a central command bus, automatic mutation retries, schema registry, all-replica fanout, reactive Cell stack, IPv6-only discovery, streaming RPC or a new SDK Maven module. Those are OPTIONAL until a concrete integration use case is approved. Production deployment decisions and upstream version support checks must use the selected release environment; this audit's local build cannot certify them.

Implementing SDK-0 does not fix Order saga/profile wiring, Inventory smoke pause expectations or Payment simulation policy. Those remain explicitly tracked application work and block SDK-8's full-product Definition of Done. A release can only narrow its supported scope through an explicit product decision, not by excluding failed tests from totals.
