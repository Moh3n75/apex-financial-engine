## Audit and decisions

The existing React Flow/Dagre graph, shared dashboard components, protocol filters, service expansion, evidence inventory, v2 DTO/Zod validation and bounded server-only HTTP client were reusable. They were extended incrementally. No parallel frontend topology model or deployment system was introduced.

Kafka projection already supported exact contract joins. The missing local relationships came from absent effective manifests: local Cells were not advertising Contract Discovery, while the configured secure pollers required separately configured owner destinations. A local-only opt-in transport now collects the **same ContractDiscoveryProvider** output from the existing Eureka registry. This fixes provider integration rather than supplying a static graph.

The platform exposes gRPC handlers, discovery/channel factories and generic QueryGateway/RequestReplyGateway invocation. Handler registration cannot identify callers. The five reference Cells currently have no caller declarations; their missing dependencies are reported as unresolved. The sample Java gRPC client does invoke Order contracts and now declares those dependencies alongside its real destination constant. It was compiled/packaged but was not started or used to issue business commands in this acceptance run.

## Sources and matching rules

### HTTP

`GatewayRouteTopology` reads actual registered Gateway routes, then joins route definitions by **exact route ID and destination URI** to attach sanitized Path/Method predicates and filter names. A definition without a registered route cannot create a connection. Visible logical service endpoints and environment must agree. Raw URLs, filter arguments, headers and arbitrary predicate arguments are excluded.

All seven captured route IDs start with `ReactiveCompositeDiscoveryClient_` and target CUSTOMER-CELL, PAYMENT-CELL, APEX-OPERATIONS-CONSOLE, INVENTORY-CELL, ORDER-CELL, REPORTING-CELL and APEX-API-GATEWAY respectively. Their actual predicates are `Path: /<lowercase-service>/**`; their registered filter is RewritePath with arguments redacted. The Gateway self-route is retained because it is an actual registered route. No HTTP edges are inferred from co-registration or Kafka/gRPC capabilities.

The server-side reader has a 1.5-second exchange deadline, incremental 64 KiB body limits, at most 128 records and a five-second cache. Missing definition detail produces partial coverage while retaining independently confirmed registered routes.

### Kafka

`ContractDiscoveryProvider` reads effective `PublisherRouting`, existing `PublishedContracts` catalogs, `ConsumerTopics`, configured group IDs and actual `EventHandlerRegistry` descriptors. These are the existing messaging/outbox infrastructure used by CellEvents and the Kafka publisher/consumer runtimes. Messaging itself was not redesigned.

`ContractTopology` joins **environment + logical Kafka cluster + effective topic + event type + version**. A consumer link additionally requires its subscription, group and registered matching handler. Each matched path is Publisher SERVICE → KAFKA_TOPIC → CONSUMER_GROUP → Consumer SERVICE. Shared links preserve every contract/path and its provenance. A publisher with no visible match remains visible with an explicit unresolved consumer.

`apex-local-kafka` is an explicitly configured logical cluster identity. It is not broker-attested. Subscription and handler registration do not prove listener execution, delivery, processing or successful business workflows.

### gRPC

`GrpcCallerDeclarations` is a bounded, sanitized bean catalog using existing annotated Java request/query DTO classes and logical destinations. It does not intercept or change invocation. ContractDiscoveryProvider derives kind/type/version using the same Java contract metadata as the gateways. Explicit local routes are excluded from remote dependencies. Discovery/configuration availability is separate from health.

An edge requires a caller declaration and a visible target manifest with an exact kind/type/version handler in the same environment. It carries caller, target, request/query kind, discovery target and declared request/response behavior. Missing callers, targets or matching handlers remain unresolved. Disabled target servers are stated explicitly. There is no fallback from denied secure discovery to a weaker transport.

The sample client's shared `ORDER_TARGET` constant is used both at actual call sites and in these declarations:

```java
new GrpcCallerDeclarations(List.of(
    new GrpcCallerDeclarations.Dependency(ORDER_TARGET, GetOrderQuery.class,
        "SYNCHRONOUS_REQUEST_RESPONSE"),
    new GrpcCallerDeclarations.Dependency(ORDER_TARGET, CreateOrderRequest.class)));
```

Generic REQUEST_RESPONSE does not claim synchronous-only execution; the sample also has asynchronous request calls. Dynamic destinations are not inferred automatically. Adding another properly configured Cell with effective contracts requires no frontend relationship changes.

Discovery **v1 remains schema 1**, omitting the new empty caller field. A strict legacy RpcCodec compatibility test verifies this. `OPS_CONTRACT_DISCOVERY:2` returns schema 2 with caller metadata. Secure Console/runtime pollers select it only with `apex.ops.contract-discovery.contract-version=2`; deployments must authorize that exact query contract for their existing peers. Existing mTLS, owner authorization and strict codec behavior were retained. No fallback bypasses a rejected peer.

## DTO, browser and UI

TopologySnapshot v2 gains optional structured connection details, mirrored and validated in Zod. Old constructors and detail-less snapshots remain accepted. Kafka references, cluster scope, contract/version and protocol agreement are checked; HTTP destinations and gRPC caller/target must agree with endpoints. Browser code uses the existing BFF only.

Visual edges may aggregate identical source/target/protocol pairs. Each bundle retains its original connection objects and a contract selector. Node details expose capabilities and unresolved contracts; connection details expose route predicates/filters, complete Kafka paths or gRPC caller/request/query metadata. Service focus selects actual dependency paths; full overview, pan, zoom, automatic layout, fit, instance expansion and protocol filters remain available. API Gateway is a service role inferred from actual Gateway evidence, not an additional incompatible DTO kind.

The real topology exceeded the former 64 KiB BFF budget. Only topology now permits 256 KiB. Other endpoints retain 64 KiB. The four-second entire-exchange timeout, concurrency budget and incremental streamed-body enforcement remain intact and tested. Oversized graphs fail explicitly rather than silently truncating relationship JSON.

## Local setup and repeatable verification

Reuse [the existing local admin setup](control-center-local-admin.md) for Eureka, Gateway, Console and Next.js. Keep `APEX_OPERATIONS_API_ORIGIN=http://127.0.0.1:9190`, fixture mode false, and the existing local auth-off switches for this local session. The Console still binds literal loopback and uses its `local` profile. Add these process settings before starting it:

```powershell
$env:APEX_OPS_LOCAL_CONTRACTS_ENABLED='true'
$env:APEX_KAFKA_LOGICAL_CLUSTER='apex-local-kafka'
```

Build/install updated platform artifacts before packaging the existing Cell applications. Cell projects and sample-grpc-client are standalone Maven projects, not root reactor modules. Use their existing POMs/integration harness and the existing `-Dmaven.jar.forceCreation=true` packaging approach so a cached Boot JAR does not retain old nested platform dependencies. Do not replace an artifact while its process is using it. Existing datasource/Kafka prerequisites and credentials remain externally configured; these scripts neither create infrastructure nor rewrite configuration files.

The Cell opt-in is profile `local-ops`, explicit environment `local`, the same logical cluster and metadata flag `apex-contract-discovery-http=true`. Its GET-only `/ops/v1/contracts` delegates to the existing provider's extended manifest. Both literal loopback binding and loopback remote address are required. The listener is absent without the profile and flag. It does not start a gRPC server, change authentication, or attest runtime membership.

From a PowerShell session with Java 21 configured, after packaging the existing apps:

```powershell
# Explicitly restart only verified local repository Cell processes; start missing packaged Cells.

pnpm exec playwright test e2e/live-communication-graph.spec.ts `

```

On machines blocking local scripts, use a process-only `powershell -NoProfile -ExecutionPolicy Bypass -File <script>` invocation; no persistent execution policy change is needed. Console refreshes advertisements every five seconds; registry propagation/lease eviction can add delay. Disappeared sources replace the local collection instead of retaining fabricated successful connections. Re-run the verification script to write a new redacted receipt. The script performs reads only; the separate opt-in setup script performs the explicitly requested local process restarts.

Local collection enumerates at most 16 advertised UP instances using the existing EurekaClient. It requires fresh local registry evidence, rejects foreign environments/nonlocal endpoints/known wrong clusters, applies 1.2-second whole-exchange and 64 KiB limits, and reports differing replica declarations or unknown clusters as partial. Unknown clusters cannot form Kafka joins. It is explicitly `LOCAL_HTTP_NOT_ATTESTED`; secure runtime membership remains a separate capability. Registry instance nodes keep null epochs and unknown health.

## Remaining gaps

- No five-Cell business gRPC caller declarations exist, so live gRPC relationship acceptance is limited to accurate unresolved reporting. Positive request/query edges are tested, not claimed as live. The sample declaration demonstrates the API but is not a running service in this capture.
- No OpenTelemetry observed-interaction provider is configured. No traffic, latency, processing success, trace or workflow execution is claimed.
- No Kafka AdminClient provider is configured. Topics/groups here are effective declarations, not independently verified broker resources or offsets. Logical cluster identity is operator configured.
- No independent runtime health or authoritative local instance attestation is provided. Eureka UP and local HTTP reachability do not establish healthy business services or duplicate-instance membership.
- The local collector is deliberately not transport-attested. Production must retain the existing secure discovery/authentication and explicit v2 peer authorization; this development profile is not production readiness.
- Arbitrary route predicate/filter arguments are redacted. Dynamic gRPC destination dependencies require explicit declarations. Provider limits can produce partial coverage and large BFF responses can fail their explicit size budget.
- Actual business workflow execution, broker outages, full five-Cell secure gRPC discovery and full-repository CI were not exercised in this phase.
